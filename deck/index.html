The mod

jev-router: one question, two hooks

prompt.submit

Your prompt

Jev picks a model. If it’s sure enough, that turn runs on it. No /model.

agent.spawn

Every subagent

Jev picks a model for the subagent’s task. The subagent starts on it.

No key, or Jev is down? The prompt goes through untouched.

The whole prompt

The routing logic is three sentences

Disagree with the lines? Edit the sentences.

The catch

Switching models throws away the cache

Main thread

A trade

The new model re-reads the whole conversation. On a long session, that can cost more than it saves.

Subagents

Free

They start fresh anyway. Route every one.

So the mod only switches the main thread when Jev is at least 70% sure.

Know the limits

When not to use a decision model

You need words

Replies, code, summaries. Use the LLM.

You need several hops

Look up, think, look up again. That’s System 2.

It’s a hard rule

“Refunds over $500 need a manager” is an if. Write it.

A fixed list guarantees the shape, not the truth.

Trust, but count

Check the calibration on your own data

Model saidAnswers in bucketActually rightVerdict
90 to 100%5046 (92%)Calibrated
70 to 90%3024 (80%)Calibrated
Below 70%209 (45%)Send to a person

Example numbers. A hundred labeled tickets and an afternoon gets you yours.

Take home

Three things

  1. Color your agent’s steps with npm run color. Count the decisions.
  2. Move them to a decision model. Let code own the threshold.
  3. Measure calibration on your data before you trust anyone’s.

My bet: in a year, agent harnesses ship a decision model next to the LLM by default.

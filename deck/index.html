The pattern

Decide before you generate. Check after.

Choice · before

What do they want?

Meeting, pricing, info, or unclear. One cheap call picks the path before the agent runs.

Yes or no · after

Does the draft promise anything?

A discount, a date, a feature. The fast model checks the slow model’s work.

The do-not-contact check never reaches Jev. It’s a rule, so it’s an if.

Code owns the line

The whole policy is one function

Step Functions branches on the label. No numbers live in the state machine.

demo/src/policy.pypolicy
SURE_ENOUGH = 0.8
LIKELY_NOTHING = 0.3
LIKELY_PROMISE = 0.5

def route(receipt, sure_enough=SURE_ENOUGH):
    intent = receipt['intent']
    unclear = intent['probabilities']['unclear']
    if intent['choice'] == 'unclear' \
            or unclear >= LIKELY_NOTHING:
        return 'skip'
    if 'promises' not in receipt:
        return 'draft'
    if intent['confidence'] < sure_enough \
            or receipt['promises'] >= LIKELY_PROMISE:
        return 'approve'
    return 'send'

Know the limits

When not to use a decision model

You need words

Replies, code, summaries. Use the LLM.

You need several hops

Look up, think, look up again. That’s System 2.

It’s a hard rule

“Don’t email people who opted out” is an if. Write it.

A fixed list guarantees the shape, not the truth.

Trust, but count

Check the calibration on your own data

Take home

Three things

  1. Color your agent’s steps with make color. Count the decisions.
  2. Move them to a decision model. Let code own the threshold.
  3. Measure calibration on your data before you trust anyone’s.

My bet: in a year, agent harnesses ship a decision model next to the LLM by default.
